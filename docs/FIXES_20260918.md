## 一、修了什么（按严重度）

### P0 · AI 引擎刷新记账被"验证"门控 → 无限烧天空石
- `bot/AiBotEngine.kt` `confirmRefresh()`：把 `refreshes++ / skystonesSpent += 3 / counters()`
  移到 `guardedTap(确认)` **之后立即执行**，`waitShopLoaded` 的结果只决定要不要
  `handledClear()`。
- 语义定死为 **ACTION → COMMIT**：动作发生即记账，验证只影响后续决策。
  与 `BotEngine.doRefresh()`（2026-09-17 已修）对齐。
- 顺带：`guardedTap` 返回 false（会话已失效/坐标非法）时不记账 —— 那种情况钱并没花。

### P1 · 购买计数同样被验证门控
- `AiBotEngine.confirmPurchase()` / `BotEngine.finalPurchase()`：`countPurchase()` 改为
  在点下「购买」后立即调用；"弹窗关闭"验证只负责 `handledAdd` 与结果日志。
- 影响：`goldSpendCap` 不再能被超出（旧版弹窗关得慢时商品已买下却不计数）。

### P1 · 漏买根因：点击没生效被当成"这行处理完了"
- `AiBotEngine.verifyDialog()`：删掉 CLICKABLE 分支里的 `handledAdd(t.rowY)`。
  行还在、按钮仍可购买 = **这次点击没生效**，该行依然值得买；现在只报告、不标记，
  目标保持未决交给下一轮 observe 重新决策（绝不拿旧帧坐标去点）。
- 与 `BotEngine.kt:670-692` 的同款修复对齐（那条当时只改了传统引擎）。

### P1 · native 层 use-after-free（唯一会让进程直接死掉的缺陷）
- `jni/e7ocr.cpp` / `jni/e7yolo.cpp`：加载加 `std::mutex` + **幂等**
  （已加载直接返回，**绝不再 delete**），并且改成**加载完成后才发布指针**
  （旧版 `g_ocr = new ...` 先赋值再 load，另一个线程可能拿到半初始化对象）。
- 触发路径：机器人运行中打开「装备评分」页 → 旧版会 `delete` 机器人线程正在用的
  `g_ocr` → SIGSEGV（Kotlin 的 try/catch 捕不到）。

### P1 · 模型加载失败无法被检测
- `jni/yolov8.cpp` / `jni/ppocrv5.cpp`：`load_param`/`load_model` 的返回值透出，
  失败即返回非 0 → `e7ocr.cpp` / `e7yolo.cpp` 里的失败分支不再是死代码。
- `jni/yolov8.h`：`det_target_size` 给默认值 320；`yolov8.cpp` 析构里那句
  `det_target_size = 320`（明显笔误）删除。

### P1 · 主线程整图解码 → OOM
- `MainActivity.kt`：新增 `decodeFileSampled / decodeStreamSampled`（`inJustDecodeBounds` +
  2 的幂次 `inSampleSize`，目标宽 1080），三个 helper 全部改走采样，
  并捕 `OutOfMemoryError`。`ThemeSteam` 的 `remember` 补 `cfg.bgImage` key。

### P1 · BA 主题「开始」按钮静默失效
- `ui/ThemeBlueArchive.kt`：补上与 Steam 同一道 `riskAccepted` 闸门 + 风险弹窗，
  并在服务未开启时给提示、启动后给 toast（旧版既无弹窗也无提示，点了完全没反应）。

### P1 · 静默改写全设备级无障碍安全开关
- `ShopAccessibilityService.ensureAccessibilityNotAutoDisabled()`：**删除**
  `accessibility_turn_off_switch = 0` 的全局写入，只保留 `skip_package` 豁免；
  且整段行为改为由设置页新开关 `acc_exempt`（`AppConfig.accExemptFromAutoOff`，
  默认开）显式授权。关掉后不再修改任何系统设置。

### P2 · 并发与健壮性
- `handledRows`：裸 `HashSet` → `ConcurrentHashMap.newKeySet()`（迭代弱一致，不会抛 CME）；
  `clear()` 从主线程移进 bot 线程（join 旧线程之后），消除"旧线程把上一轮行号补回来"的逻辑竞态。
- `didScroll`：每次调用 2×8.7MB 的 `IntArray` 改为**按线程复用的缓冲**
  （`ThreadLocal`），`catch (Exception)` → `catch (Throwable)`（OOM 是 Error，旧版捕不到）。
- `Humanizer`：4 处 `Thread.sleep` 改走 `sleepQuietly`（恢复中断标志后安静返回）——
  正常停止不再被记成 `E7SA.Crash InterruptedException`，玩家不会再被假异常误导。
- 新增 `E7App`（Application）：全局 `UncaughtExceptionHandler` 把未捕获异常追加到
  `Android/data/com.e7.shop/files/e7sa_crash.log`（上限 1MB），补上"引擎循环之外的崩溃
  只进 logcat、过夜就被冲掉"的空白。
- `AppConfig`：`delayMinMs/delayMaxMs` 加硬边界（50ms ~ 30s）——旧版无校验，
  输入框可填 9 位数，表现为"机器人卡死"。

### P2 · 安全与隐私
- `res/xml/backup_rules.xml` + `data_extraction_rules.xml`：排除 `file/debug_last.png`
  （全屏游戏截图，隐私内容 + 体积大会挤爆 25MB 备份配额）与 `external` 整个域
  （运行日志与原始截图采集）。
- `AndroidManifest.xml`：补 `rikka.shizuku.ShizukuProvider` 声明（官方要求，AAR 清单里没有）
  → 让「一键开启无障碍」的通道二真正可用；`proguard-rules.pro` 补对应的 keep
  （R8 曾把它当无用代码删掉，usage.txt 有记录）。

### 新增单测覆盖什么
- `ClickGateTest`：最终点击闸门的 6 条断言 —— 合法点必点一次、边界值合法、
  会话已停止 / NaN / 负坐标 / 越界 四种情况**绝不点击**。
  （此前闸门零测试，而全库所有决策点击都要过它。）
- `PurchaseGuardTest`：`priceMatches` 的严格唯一语义 —— 价格出现两次要拒绝、
  7 位数不能被 6 位前缀匹配、错品类要拒绝。
