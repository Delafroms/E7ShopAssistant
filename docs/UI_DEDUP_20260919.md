# E7SA 第六轮（2026-09-19 深夜）：UI 代码质量——两个主题的去重（行为+共用弹窗）

> 触发：用户「能优化UI代码质量吗？」
> 结果：**元素树零差异、像素级等价**（见验证），两主题重复行从 420 行降到约 300 行。

## 一、先解决"看不见图怎么验证"的问题

本机无法看图（模型不支持图像输入），所以先搭了一套**对拍工具链**：

1. `uiautomator dump` 抓**元素树**（文本 + 中心坐标）→ 主门禁；
2. `screencap` 抓**截图** → numpy 逐像素比对 → 副门禁；
3. 先测**噪声底线**：同一版本连拍两次，得到"哪些屏天然不稳定"。

实测噪声底线：元素树**零差异**（很稳）；像素 6/8 屏 0.000%，
`steam_about` 与 `ba_run` 各约 4.3%（页面里有动画，帧相位不同）。

## 二、抽了什么（只抽逻辑与共用弹窗，渲染留在各自主题）

新增 `ui/UiCommon.kt`：

| 抽取项 | 原重复情况 | 收益 |
|---|---|---|
| `stageResOf(stage)` | 11 行 `when` 映射在两个主题各写一遍 | 阶段文案只此一份 |
| `rememberImagePicker(ctx, onPicked)` | "选图 + 持久化读权限 + 失败只记日志"在两个主题各写两遍（背景/Logo，共 4 份） | 权限处理只此一份 |
| `RiskConfirmDialog(onDismiss, onAccept)` | 风险确认弹窗（含"接受并开始"逻辑）在两个主题各一份 | **BA 曾漏掉这个闸门导致点开始没反应**，现在不可能再漏 |

## 三、验证（关键）

| 门禁 | 结果 |
|---|---|
| 元素树（8 屏 / 221 元素，文本+坐标） | **零差异** ✓ |
| 像素（6 屏） | **0.000%**（完全一致）✓ |
| 像素（`steam_about` / `ba_run`） | 4.29% / 0.10%，而**同版本连拍**同样是 4.29% / 4.42% → 动画噪声，非回归 ✓ |

## 四、诚实边界

- 只做了**逻辑与共用弹窗**的抽取；**布局层**的重复（两主题各 1000 行里仍有约 300 行逐字相同，
  且都是夹在各自布局里的片段）**没有动** —— 那需要重构两套布局树，风险与收益不成比例。
- 对拍只覆盖 4 个页面 × 2 主题；设置页的深层滚动位置、对话框弹开状态等未逐一覆盖。
