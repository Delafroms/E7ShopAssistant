## 一、预算闸门收口（原"未做项 ②"的一部分）

- 新增 `bot/BudgetGate.kt`：金币 / 天空石闸门变成**纯函数、两条管线共用**。
  原先这条规则在 `BotEngine.doBuy`、`BotEngine.doRefresh`、`AiBotEngine.budgetBlocked`
  里**各写一遍**（3 处），正是本项目的系统性坑（双管线同步陷阱）；而它管的是**真钱**。
- 新增 `BudgetGateTest`（10 例）把边界语义钉死：
  `cap<=0 = 不限制`、`spent == cap 即停（>= 语义）`、`超上限最多一件`（ACTION→COMMIT 的保守方向）、
  两个闸门对"0 = 不限制"的解释必须一致。

## 二、时序常量金值测试

- 新增 `TuningTimingTest`（3 例）：把上一轮收敛进 Tuning 的 **25 个时序常量的确切数值**钉住，
  并断言所有随机区间"下限 < 上限且为正"。
- 意义：那次重构的口号是"只改名、不改值"——这组断言让**手滑改值**立刻变红；
  有意调整时必须同步改测试，等于强制留痕。

## 三、主题重复治理：只收口**行为**，不动布局

- 实测两主题的重复是**夹在各自布局里的片段**（≥8 行的连续相同块仅 12 块 / 145 行，
  最大 25 行且在一个 Row 内部），抽取它们等于重构两套布局树 —— 而**本机无法做视觉验证**。
- 于是改做真正有风险的那一半：`ui/WebDavActions.kt` 把 WebDAV 的三个动作
  （上传 / 下载并导入 / 测试连接）抽成两个主题共用的函数。
  这两段**已经开始分叉**（Steam 是嵌套 if、BA 是合并条件式）——典型的两条管线各演化。
  现在主题里只剩一行调用，布局与配色零改动（零视觉风险）。

## 四、装机与一个容易踩的坑

- 同签名覆盖升级：`adb install -r` **Success**，数据保留。
- **坑：App 更新后系统的无障碍启用状态会被清掉** —— 本次更新后 App 显示"无障碍服务未开启"，
  需要重新写入（`settings put secure enabled_accessibility_services` 追加本服务）才恢复。
  这不是本轮的代码问题，但每次发新版都要提醒用户/自己重开一次。
