## 一、发现的真实问题（已修）：确定性失败被无限重试

**旧行为**：以下三种失败都返回 `BuyResult.FAIL`，与"点击没生效"共用同一个出口
（`noteRowFailure` —— 按玩家要求"宁可多试、绝不漏买"**永不计上限**）：

| 失败路径 | 性质 | 旧行为 |
|---|---|---|
| `dialog verify FAIL`（价格歧义 / 图标不符） | **确定性**（同样的画面再点还是同样结果） | 无限重试 |
| `rowBuyPoint == null`（找不到购买键） | 确定性 | 无限重试 |
| `confirmPt == null`（弹窗里找不到确认键） | 确定性 | 无限重试 |

**证据**（红队日志，时间被压缩到每轮 3 帧）：同一行的购买键被点了 **63 次 / 182 次**。
真机上等价于"机器人一直点同一个位置"，既暴露异常行为特征，也让玩家无法判断它在工作还是卡住。

**修法**：新增 `BuyResult.VERIFY_FAIL` + `noteVerifyFailure()` + `Tuning.ROW_VERIFY_MAX_ATTEMPTS = 3`；
达到上限后 `handledAdd` **暂时**放弃该行（刷新/滑动清零，不是永久跳过）。

**与漏买修复的边界（关键）**：「点击没生效（弹窗根本没出现、按钮仍可购买）」**不在**封顶范围，
那条路径继续"永不放弃该行"—— `BotEngineFsmTest.click_without_dialog_does_not_mark_row_handled` 仍然全绿。

## 三、我误判为"突破"的两条（攻击设计有误，不是引擎问题）

1. **价格歧义**：`priceMatches` 的语义是"**恰好一条**等于期望价"，我第一版攻击放的是
   "184000 + 999999"（后者不等于期望价，属正常干扰项）→ 引擎正确地忽略了它。
   真正的歧义是**两条相同的期望价**。
2. **弹窗永不关闭**：引擎超时时按设计**保守计数**（钱可能已花），但必须写 `UNCONFIRMED`、
   **绝不写 `PURCHASE COMMIT`** —— 这正是"假阳性比没有记录更危险"的落地。我第一版断言写成
   "不得计数"，与设计冲突。

## 四、待续（显式 @Ignore，附原因）

3 条用例（点错行 / 价格歧义封顶 / 弹窗永不关闭）的 **Attacker 编排与引擎路径未对齐**：
Attacker 在"点过行内购买"后**永久返回弹窗帧**，导致引擎在 SCAN 阶段看到弹窗 → 进 RECOVER 循环，
断言因此误报。**需要**：让 Attacker 按"当前是否处于购买流程"编排，而不是按"历史上是否点过"。

因此：封顶修复目前只有「代码 + 未回归」级证据（钱路径与漏买用例仍绿），
**封顶行为本身还没有自动化证据** —— 下一轮把编排修好后补上。
