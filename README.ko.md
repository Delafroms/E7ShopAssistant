# E7SA — E7 Shop Assistant (E7 상점 도우미)

[![Issues](https://img.shields.io/badge/Issues-welcome-blue?logo=github)](../../issues) [![Releases](https://img.shields.io/badge/Releases-latest-green?logo=github)](../../releases)

> **위험 고지**: 이 도구는 접근성 서비스를 통해 『에픽세븐』을 자동 조작합니다.
> **게임 이용약관을 위반할 수 있으며 계정 위험이 있습니다**. 사용에 따른 책임은 사용자에게 있으며,
> 이 프로젝트는 Smilegate와 아무런 관련이 없습니다.

E7SA는 『에픽세븐』 **비밀 상점**을 위한 보조 도구입니다: 스크린샷 → 인식 → 판단 → 탭.
목표 상품을 자동으로 구매하고, 살 것이 없으면 상점을 새로고침합니다.

- 언어: [简体中文](README.zh-CN.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

> **문서 안내**: 이 문서는 한국어판입니다. **전체 정보(가장 완전한 버전)** 는 중국어 주 문서
> **[README.zh-CN.md](README.zh-CN.md)** 를 참조하세요. 아래 「테스트 상태」·「알려진 문제」는
> 그 문서와 **동일한 기준**으로 작성되었습니다(한쪽은 "검증됨", 다른 쪽은 "미검증"이라고 말하지 않습니다).

## 개요

비밀 상점은 새로고침마다 6칸만 표시되고 목표 상품의 등장 확률은 낮습니다(칸당 서약서표 약 0.66%,
신비 메달 약 0.17%). 수동 새로고침은 부담이 크므로 "보기 → 판단 → 탭" 과정을 자동화합니다.
목표는 다음 세 가지뿐입니다.

1. **구매 누락 0** — 살 수 있는 목표를 보면 반드시 구매;
2. **오구매 0** — 근거가 부족하면 잘못 탭하는 대신 아무것도 하지 않음;
3. **예산 통제** — 골드와 하늘석(유료 재화)에 상한을 둠.

**개발 단계**: v1.0.0은 첫 공개 버전이며 **개인 프로젝트**입니다(상업용 제품이 아닙니다).
**테스트 완전성**: 단위 테스트와 적대적 테스트는 시뮬레이션 계층에서 통과했습니다. 실기기 검증은 설치,
실행, UI, 클라우드 동기화만 해당합니다. **장시간 연속 실행은 검증되지 않았습니다**("테스트 상태" 참조).

## 구현된 기능

- **두 개의 인식 엔진**: YOLO 시각 인식 / 전통적 CV("구매" 버튼 텍스트로 행 구조 추정 + 아이콘 영역 색상 서명 + 텍스트 검증)
- **두 개의 독립 탭 파이프라인**: AI 탭(YOLO를 눈으로 + 전용 의사결정 상태 머신)과 전통 탭(텍스트 앵커). 서로 대체 동작하지 않습니다
- **예산 게이트**: 골드 상한, 하늘석 상한, 서약서표/메달 보유 상한. 도달 시 중지
- **대기 전력 관리**: 실행 중 화면 켜짐 유지, 작업 완료 시 자동 화면 잠금(설정 가능)
- **플로팅 작업 패널**: 상태, 단계, 통계, 이벤트 로그, 시작/일시정지/중지(드래그 가능)
- **기록**: 세션 기록, 누적 구매와 소비
- **장비 점수**: 스탯 가중치로 장비 가치를 계산 (속도 x2.0, 치명타율 x1.5, 치명타 피해 x1.1, 퍼센트 x1, 고정 공격/방어 x0.3, 고정 HP x0.15)
- **진단 도구**: 원본 프레임 캡처, 인식 회귀 벤치(버전 표시 길게 누르기)
- **네 가지 테마**(Steam 다크 카드 / Steam OLED 블랙 / Blue Archive 라이트 / DeepSeek)와 중국어·영어 UI
- **선택적 클라우드 동기화**: WebDAV(사용자 서버와 자격 증명). 설정하지 않으면 네트워크 통신이 없습니다

*Experimental(사용 가능하나 검증 중)*: 슬립 모드(전체 프레임 인식, 느리지만 안정적), 사용자 배경 이미지와
상단 타이틀 이미지, 테마 전환 이징 선택.

## 아키텍처

```
스크린샷(접근성 서비스)
  → 전처리(확대/축소, 해상도 비의존 샘플링 윈도)
  → 장면 판정(상점 목록 / 구매 대화상자 / 새로고침 대화상자 / 네트워크 오류 / 기타)
  → 후보 검출(YOLO 아이콘 박스 ∪ OCR 상품명 행)
  → 특징 추출("구매" 버튼 행간으로 행 구조, 아이콘 색상 서명)
  → OCR(PP-OCRv5)
  → 다중 신호 융합(텍스트 + 아이콘 방증 + 가격 유일 일치)
  → 필터(품절, 처리된 행, 유형 스위치)
  → 의사결정(BotEngine 전통 / AiBotEngine AI)
  → 최종 클릭 게이트(ClickGate: 좌표 유효, 세션 중지 아님) → 제스처
```

- **계층 분리**: 인식 계층은 "무엇이 보이는가", 판단 계층은 "무엇을 할까", 장치 계층은 "화면을 가져오고 누르기"만 담당합니다.
- **AI 파이프라인은 대체 동작하지 않습니다**. 확신이 없으면 보고하고 움직이지 않습니다.
- **ACTION → COMMIT**: 상태를 바꾸는 동작(구매, 새로고침, 예산 차감)은 **동작이 일어난 순간** 기록되며, 검증은 이후 판단에만 영향을 줍니다.
- 네이티브 C++가 ncnn 추론을 담당하며, 모델은 `assets/e7sa_yolo.ncnn.meta`로 자기 서술됩니다.

## 설치와 사용

**요구 사항**: Android 11(API 30) 이상, arm64-v8a 또는 armeabi-v7a.
실기기 검증은 OnePlus PLR110 / Android 16 / ColorOS만 해당하며, 다른 기기와 제조사 ROM은 미검증입니다.

1. 이 저장소의 Releases에서 APK를 설치합니다.
2. 앱을 열고 **접근성 서비스**를 활성화합니다(스크린샷과 제스처에 필수).
3. 선택: adb로 `WRITE_SECURE_SETTINGS`를 부여하면 원탭 활성화를 쓸 수 있습니다:
   `adb shell pm grant com.e7.shop android.permission.WRITE_SECURE_SETTINGS`
4. 위험 확인 대화상자에 동의한 뒤 『에픽세븐』 비밀 상점을 열고 "시작"을 누릅니다.
5. 먼저 **골드 상한**과 **하늘석 예산**을 설정하세요(0 = 무제한).

**중지**: 플로팅 패널 또는 앱의 "중지". 다시 "시작"하면 이전 세션을 종료하고 통계를 초기화한 뒤 현재 화면에서 재개합니다.

**복구**: 오랫동안 아무 동작이 없으면 접근성 서비스가 켜져 있는지 확인하세요(앱 업데이트 후 OS가 끌 수 있습니다).
앱은 일반적인 경우를 자가 복구합니다(무효 탭 → 백오프 재시도, 잔여 대화상자 → BACK 전송).

**문제 보고**: 아래 "버그 보고" 참조.

## 보안 검증과 레드팀 테스트

### 테스트 목표

"동작한다는 것을 증명하는 것"이 아니라 **"망가뜨릴 수 없다는 것을 증명하는 것"** 입니다.

### 테스트 범위와 방법

- **범위**: 인식 계층 기만(품절 행, 가짜 구매 버튼 위치, 잘못된 행 탭, 가격 모호성) + 타이밍 기만(확인 탭이 삼켜짐, 대화상자가 닫히지 않음)
- **방법**: `RedTeamFsmTest` 적대적 케이스 — Attacker가 공격 대상 화면을 구성하고, 피검증 대상은 의사결정 상태 머신 자체입니다.
  "설계대로 동작함"을 확인하는 일반 테스트와 분리하여, 엔진을 속일 수 있는 장면만 따로 구성합니다

### 테스트 결과

| 공격 시나리오 | 결과 |
|---|---|
| 품절 행 | **방어선 차단** — 단 한 번도 탭하지 않음 |
| 가짜 구매 버튼("구매" 텍스트를 아이콘 왼쪽에 배치) | **방어선 차단** — 탭하지 않음(구매 키가 후보 오른쪽에 있을 것을 요구) |
| 잘못된 행 탭(행 안은 서약서표, 대화상자는 메달) | **방어선 차단** — 즉시 해당 행을 포기하고 취소하며, 확인하지 않음 |
| 가격 모호성 / 대화상자 내용 불일치 | **방어선 차단** — 구매를 확인하지 않음. 3회 연속이면 해당 행을 일시 포기 |
| 대화상자가 영영 닫히지 않음(탭이 시스템에 삼켜짐) | **방어선 차단** — 타임아웃 시 보수적으로 집계하되 **가짜 성공 기록은 절대 남기지 않음**(UNCONFIRMED만 기록) |

### 레드팀이 발견한 문제(수정 완료)

**RT-001｜확정적 실패의 무한 재시도**: 같은 행의 `dialog verify FAIL`, 구매 키를 찾을 수 없음,
확인 키를 찾을 수 없음이라는 세 가지 **확정적** 실패가 원래는 "탭이 적용되지 않음"과 같은 출구를 공유했고,
후자는 "누락보다 과시도가 낫다"는 원칙에 따라 상한이 없었습니다 → 실측 결과 같은 버튼이 **63회 / 182회** 탭되었습니다.
수정 완료: 별도 예산을 신설하여 3회에 도달하면 해당 행을 **일시** 포기합니다(새로고침/스크롤 시 초기화되며 영구 건너뛰기가 아닙니다).

**경계(중요)**: **"탭이 적용되지 않음(대화상자가 아예 뜨지 않고 버튼이 여전히 구매 가능)"** 은 상한 범위에
**포함되지 않으며**, 이 경로는 계속 "해당 행을 절대 포기하지 않음"을 유지합니다 —
복구 가능한 실패이므로 포기하는 것은 곧 구매 누락이기 때문입니다.

### 이 검증이 **아닌** 것

- 완전한 보안 감사가 아닙니다: 범위는 위의 공격면만 포함하며, 침투 테스트·코드 감사·형식 검증은 하지 않았습니다;
- "문제를 발견하지 못했다"는 "절대 안전하다"와 같지 않습니다: 레드팀 케이스가 다루는 것은 **알려진** 실패 모드입니다;
- 레드팀 케이스가 검증하는 것은 **의사결정 상태 머신**(시뮬레이션 계층)이며, **실기기 동작은 하나씩 재현하지 않았습니다**.

## 알려진 문제(Known Issues)

전체 결함 대장(RT-001 ~ RT-014): [docs/TEST_REPORT.md](docs/TEST_REPORT.md).
레드팀 대항 테스트 원본 기록: [docs/REDTEAM_20260919.md](docs/REDTEAM_20260919.md).

| 번호 | 문제 | 상태 |
|---|---|---|
| RT-004 | 네이티브 계층 use-after-free(실행 중 장비 점수 페이지를 열면 프로세스 크래시, 유일한 프로세스 수준 크래시 결함) | 수정 완료, **실기기 재현 검증 미실시** |
| RT-005 | 모델 로드 실패를 감지할 수 없음 | 수정 완료, **미검증** |
| RT-009 | 덮어쓰기 설치 후 접근성 활성화 상태가 시스템에 의해 해제됨 | **플랫폼 동작**, 수정하지 않음. "업그레이드 시 주의사항" 참조 |
| RT-010 | 두 테마의 레이아웃 코드에 중복이 남아 있음(기술 부채, 기능 영향 없음) | 부분 수정 |
| RT-011 | 지속적 통합(CI) 부재 | CI는 제공되었으나 실제 저장소에서 아직 통과한 적 없음 |
| RT-012 | 인식 정확도는 모델과 화면 조건의 제약을 받음(극단적 해상도, UI 배율, 가림, 애니메이션 중간 프레임에서 누락 가능) | **알려진 제한**, 수정하지 않음 |
| RT-013 | 자동 조작은 **이용약관을 위반할 수 있으며** 계정 위험이 있음 | **알려진 위험**, 첫 실행 시 확인 요구 |
| RT-014 | 접근성 서비스가 필요하고, 원탭 경로는 높은 권한을 요구 | 설계상의 트레이드오프 |

**기타 알려진 제한**:

- `slot6Check`와 `revealSlot6` 두 곳의 스와이프 기하 span이 약 2.7배 차이(0.72h vs 0.27h)이며, 통일하려면 먼저 실기기 회귀가 필요합니다;
- 행 허용 오차의 clamp 하한은 화면 높이의 10%(1272 화면에서 약 127px)이므로, 행간이 이보다 작으면 여전히 행을 넘어 탭할 위험이 있습니다(E7 상점의 행간은 고정 약 20%라 발동하지 않음);
- 고아 문자열 84개와 `appearance_m3`의 중국어 번역 누락, V1.1에서 정리 예정.

## 업그레이드 시 주의사항

1. **서명 변경(중요)**: v1.0.0은 정식 배포 키를 사용합니다. 초기 **디버그 서명** 버전에서 업그레이드하려면
   **반드시 먼저 삭제**해야 합니다(기기 설정과 클라우드 동기화 자격 증명이 지워집니다. 통계는 먼저 WebDAV로
   업로드하고 재설치 후 내려받으면 됩니다). 같은 서명 버전끼리는 덮어쓰기 업그레이드가 가능합니다.
2. **접근성 해제**: 앱 업데이트(`adb install -r` 포함) 또는 `am force-stop` 후에는 시스템의 접근성
   활성화 상태가 **해제됩니다**(플랫폼 동작, RT-009). 업데이트 후 "접근성 서비스가 꺼져 있습니다"라는
   안내가 나오면 다시 한 번 켜면 됩니다.
3. **서명 키 분실 = 이미 설치한 사용자에게 업데이트를 배포할 수 없음** — 사용자 지정 키를 쓰는 구조적
   대가이며, 여기에 기록해 둡니다.
