## 1. 项目简介与定位

E7SA 是一个面向《第七史诗》（Epic Seven）**神秘商店**的辅助工具，把「看画面 → 判断 → 点击」这条链路自动化：
截图 → 识别 → 决策 → 点击，自动购买目标商品，无可买目标时刷新商店。

**定位**：个人自用工具，开源出来供有相同需求的人使用。不做营销包装，不承诺稳定性。

**设计目标只有三条**：

1. **零漏买** —— 识别到可买的目标就一定要买到；
2. **零误买** —— 证据不足时宁可不买，也不点错；
3. **预算可控** —— 金币与天空石（付费货币）都有硬闸门。

**当前状态**：v1.0.0 为首个公开版本。单元测试、状态机整机测试与对抗性测试在**模拟层**通过；
真机验证仅覆盖安装、启动、界面与云同步；**长时间连续运行尚未验证**。

## 2. 项目解决的问题

神秘商店的机制决定了人工刷新的成本很高：

| 项目 | 数值 |
|---|---|
| 每次刷新格数 | 6 格（一屏可见 5 格，下滑揭示第 6 格） |
| 誓约书签 | 单格出现率约 **0.66%**，单价 **184,000 金币** |
| 神秘奖牌 | 单格出现率约 **0.17%**，单价 **280,000 金币** |
| 刷新成本 | **3 天空石**（付费货币） |

按这个概率，人工盯着屏幕反复刷新既枯燥又容易错过。E7SA 把这个过程自动化，并且用
「证据不足就不动手」的原则来避免买错 —— 买错一次的代价远大于多刷几次。

## 3. 核心功能

### 已实现

- **双识别引擎**：YOLO 视觉识别 / 传统识图（由「购买」按钮文本推导行结构 + 图标区颜色签名 + 文本校验）
- **双点击管线**：AI 点击（YOLO 为眼睛 + 独立决策状态机）与传统点击（文本锚点），两条管线互不回退
- **预算闸门**：金币上限、天空石上限、书签/奖牌持有上限；达到上限即停止
- **挂机省电**：运行期间保持屏幕常亮，任务完成或达上限后可按设置自动熄屏
- **悬浮任务面板**：状态球（呼吸脉冲）+ 阶段字母 + 统计 + 事件日志 + 开始/暂停/停止，可拖拽
- **记录与统计**：会话历史、累计购买与消耗
- **装备评分**：按词条权重计算装备价值（速度 ×2.0、暴击率 ×1.5、暴击伤害 ×1.1、百分比 ×1、固定攻击/防御 ×0.3、固定生命 ×0.15）
- **诊断工具**：原始帧采集、识别回归台（长按版本号触发）
- **四套主题**（Steam 深色卡片 / Steam OLED 纯黑 / Blue Archive 明亮学院 / DeepSeek）+ 中英文界面
- **可选云同步**：WebDAV（用户自备服务器与凭据），不配置则不联网

### Experimental（可用但仍在验证）

- 睡眠模式（每帧完整识别，更慢更稳；**对 AI 点击管线无行为差异**）
- 自定义背景图与顶部标识、主题切换动画函数选择

## 5. 技术架构与设计原则

```
截图（无障碍服务）
  → 预处理（缩放/裁剪，分辨率无关的采样窗）
  → 场景判定（商店列表 / 购买弹窗 / 刷新弹窗 / 网络异常 / 其他）
  → 候选检测（YOLO 图标框 ∪ OCR 商品名行）
  → 特征提取（行结构由「购买」按钮行距推导、图标颜色签名）
  → OCR（PP-OCRv5）
  → 多信号融合（文本 + 图标旁证 + 价格匹配）
  → 过滤（售罄、已处理行、类型开关）
  → 决策（BotEngine 传统管线 / AiBotEngine AI 管线）
  → 最终点击闸门（ClickGate）→ 手势执行
```

**核心原则**（这些不是口号，都有对应的测试或代码约束）：

| 原则 | 含义 |
|---|---|
| **ACTION → COMMIT** | 任何改变内部状态的动作（购买、刷新、预算扣减）在**动作发生的那一刻**记账；验证只影响后续决策，不决定记不记账 |
| **召回优先** | 不确定时先增加观测（多看一眼、放宽窗口），而不是放弃目标 |
| **fail-closed** | 识别失败、坐标算不出、证据不足 → **不点击**，绝不猜测 |
| **单一闸门** | 所有点击都经过 ClickGate（会话有效 + 坐标合法）；其余前置条件由各调用点在点击前完成 |
| **行容差由行距推导** | 绝不用图标框高度推导（那会超过行距，导致跨行点错） |
| **双管线必须同步** | 改任一引擎都要检查另一条 —— 历史上多次出现「注释说已修、另一条没同步」 |

**分层**：`service`（生命周期/编排）· `bot`（识别与决策）· `device`（截图/手势）· `ui`（悬浮窗与主题）· `diag`（诊断）。
依赖通过构造参数注入，纯逻辑可在 JVM 单测中运行。

**换模型不需要改代码**：模型由 `assets/e7sa_yolo.ncnn.meta` 自描述（声明 imgsz 与类别），
替换 param/bin/meta 三个文件即可。

## 6. 安装与使用

**环境要求**：Android 11（API 30）及以上；arm64-v8a 或 armeabi-v7a。
**仅在 OnePlus PLR110 / Android 16 / ColorOS（2800×1272）完成真机测试**，其它机型与厂商 ROM 未经验证。

1. 从本仓库 Releases 下载 APK 并安装。
2. 打开应用 → 按提示开启**无障碍服务**（必需，用于截图与手势）。
3. 可选：通过 adb 授予 `WRITE_SECURE_SETTINGS` 以使用「一键开启无障碍」通道：
   `adb shell pm grant com.e7.shop android.permission.WRITE_SECURE_SETTINGS`
4. 首次使用需在弹窗中**确认风险**，然后进入《第七史诗》的神秘商店界面，点「开始」。
5. 建议先设置**金币消耗上限**与**天空石预算上限**（0 = 不限制）。

**停止**：点悬浮窗或应用内的「停止」。任何时刻重新点「开始」都会结束上一轮、清空本轮统计并从当前画面恢复。

**异常恢复**：若长时间无动作，先确认无障碍服务仍在运行（系统可能在应用更新后关闭它）。
应用内置「点击无效 → 退避重试」「残留弹窗 → 发送返回键关闭」等自愈逻辑。

## 7. 配置能力矩阵

本项目的配置项遵循「**消灭假开关**」原则：每一项都必须**有入口、有读者、可验证**，否则删除。
完整矩阵（20 项 + 4 个已删死配置的证据）见 [docs/V1-配置能力矩阵.md](docs/V1-配置能力矩阵.md)。

| 设置项 | 作用 |
|---|---|
| 金币消耗上限 `goldSpendCap` | 本次会话累计花掉多少金币后停止（0 = 不限制） |
| 天空石预算 `maxSkystones` | 本次会话最多消耗多少天空石（0 = 不限制） |
| 书签/奖牌上限 | 持有量达标即正常收工（走完成路径，可自动熄屏） |
| 速度倍数 | 缩放所有等待时长（有下限，避免手势被系统合并） |
| 点击偏移 0–4 | 点击点的随机偏移范围（拟人化） |
| 休息间隔 | 每 N 次操作休息一次 |
| 风险确认闸门 `riskAccepted` | 未确认风险不开始（曾在某个主题上静默失效，已修） |

**刻意「有配置无 UI」**：滑动几何 `swipeCenterX/TopY/BottomY` —— 它们是随屏幕换算的自适应参数，暴露出来只会制造误配置。

## 8. 安全与隐私

| 项目 | 说明 |
|---|---|
| 权限用途 | 无障碍服务：截图与模拟点击；悬浮窗：任务面板；通知：保活提示；`WRITE_SECURE_SETTINGS`（可选）：一键开启无障碍；Shizuku（可选）：备用授权通道 |
| 截图与识别数据 | **仅在设备本地处理**，不写入网络、不上传 |
| 是否联网 | **仅在用户主动配置 WebDAV 同步时联网**；不配置则不产生任何网络请求；无遥测、无统计 SDK |
| 保存的数据 | 应用配置、运行日志与统计（应用私有目录）；WebDAV 账号与应用密码单独存放并**排除系统备份与设备迁移** |
| 无障碍范围 | 事件订阅**限定为游戏包名** `com.stove.epic7.google`，不再改写全设备级无障碍开关 |
| 日志 | 运行日志可能包含识别到的界面文本；提交日志前请自行检查是否含个人信息 |
| 清理数据 | 卸载应用即清除全部本地数据；设置页可清理统计与日志 |

## 9. 安全验证与红队测试

### 测试目标

不是「证明它能工作」，而是「**证明它搞不坏**」。

### 测试范围与方法

- **范围**：识别层欺骗（售罄行、假购买按钮位置、点错行、价格歧义）+ 时序欺骗（确认点击被吃掉、弹窗不消失）
- **方法**：`RedTeamFsmTest` 对抗性用例 —— 由 Attacker 编排被攻击画面，被测对象是决策状态机本身；
  与「按设计工作」的常规测试分开，专门构造能骗过引擎的场景

### 测试结果

| 攻击场景 | 结果 |
|---|---|
| 售罄行 | **防线挡下** —— 一次都不点 |
| 假购买按钮（「购买」文本放在图标左侧） | **防线挡下** —— 不点（要求购买键在候选右侧） |
| 点错行（行内是书签、弹窗是奖牌） | **防线挡下** —— 立即放弃该行并取消，不确认 |
| 价格歧义 / 弹窗内容对不上 | **防线挡下** —— 不确认购买；连续 3 次后暂时放弃该行 |
| 弹窗永不关闭（点击被系统吃掉） | **防线挡下** —— 超时保守计数，但**绝不写假的成功记录**（只写 UNCONFIRMED） |

### 红队发现的问题（已修复）

**RT-001｜确定性失败被无限重试**：同一行的 `dialog verify FAIL`、找不到购买键、找不到确认键这三类
**确定性**失败，原先与「点击没生效」共用出口，而后者按「宁可多试绝不漏买」永不计上限 →
实测同一按钮被点 **63 次 / 182 次**。已修复：新增独立预算，达到 3 次后**暂时**放弃该行（刷新/滑动清零，非永久跳过）。

**边界（重要）**：「点击没生效（弹窗根本没出现、按钮仍可购买）」**不在**封顶范围内，这条路径继续「永不放弃该行」——
因为那是可恢复的失败，放弃就等于漏买。

### 这份验证**不是**什么

- 不是完整的安全审计：范围只覆盖上述攻击面，没有做渗透测试、代码审计或形式化验证；
- 「没有发现问题」不等于「绝对安全」：红队用例覆盖的是**已知的**失败模式；
- 红队用例验证的是**决策状态机**（模拟层），**真机行为未逐一复现**。

| 识别回归台 | 89 张真实截图样本，双引擎基线可比 |

### 部分验证

- **RT-001 / RT-002 / RT-003**（无限重试、漏买、预算门控）：**仅模拟层验证**，真机未验证；
- **RT-010**（主题代码重复）：仅完成逻辑层与共用弹窗抽取，布局层未动；
- **识别准确率**：回归台样本上表现良好，但样本来自单一设备与有限场景。

### 未验证

以下项目**明确没有做过**，请据此评估风险：

1. **整夜连续挂机** —— 这是唯一能证明「零漏买 / 零误买」的方式，尚未完成；
2. **RT-004 / RT-005**（native 崩溃、模型加载检测）：修复后未在真机复现验证；
3. **多机型 / 多分辨率 / 多 DPI / Android 11–15 / 平板 / 折叠屏**；
4. **权限撤销、系统回收服务、应用重启、真实断网弱网**；
5. **长时间运行的内存与耗电**；
6. **多语言界面逐屏人工核对**；
7. **CI 工作流**：已提供 GitHub Actions，但尚未在真实仓库成功运行过。

### 结论

**部分测试通过（Partially tested）**。单元与模拟层结论可信；真机长时间行为未知。
**不建议无人值守使用**（Not recommended for unattended use）。

| RT-005 | 模型加载失败无法被检测 | 已修复，**未验证** |
| RT-009 | 覆盖安装后无障碍启用状态被系统清掉 | **平台行为**，不修复；见「升级注意事项」 |
| RT-010 | 两个主题的布局代码仍存在重复（技术债，不影响功能） | 部分修复 |
| RT-011 | 缺少持续集成 | 已提供 CI，尚未在真实仓库跑通 |
| RT-012 | 识别准确率受模型与画面条件限制（极端分辨率、UI 缩放、遮挡、动画中间帧可能漏检） | **已知限制**，不修复 |
| RT-013 | 自动化操作**可能违反游戏服务条款**，存在账号风险 | **已知风险**，首次启动要求确认 |
| RT-014 | 需要无障碍服务；一键授权通道需要较高权限 | 设计取舍 |

**其它已知限制**：

- `slot6Check` 与 `revealSlot6` 两处滑动几何跨度差约 2.7 倍（0.72h vs 0.27h），统一前必须先做真机回归；
- 行容差的夹取下限是屏高的 10%（1272 屏上约 127px），行距小于此值时仍有跨行风险（E7 商店行距固定约 20%，不触发）；
- 84 条孤儿字符串与 `appearance_m3` 缺中文翻译，计划 V1.1 清理。

## 12. 升级注意事项

1. **签名变更（重要）**：v1.0.0 使用正式发布密钥。从早期**调试签名**版本升级**必须先卸载**（会清除本机配置与云同步凭据；
   统计可先 WebDAV 上传，重装后再下载）。同签名版本之间可覆盖升级。
2. **无障碍会掉**：应用更新（含 `adb install -r`）或 `am force-stop` 后，系统的无障碍启用状态**会被清掉**（平台行为，RT-009）。
   更新后如果提示「无障碍服务未开启」，重新开启一次即可。
3. **签名密钥丢失 = 无法再给已装用户发更新** —— 这是使用自定义密钥的固有代价，已在此记录。
