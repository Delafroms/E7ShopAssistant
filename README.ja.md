# E7SA — E7 Shop Assistant（E7 ストアアシスタント）

[![Issues](https://img.shields.io/badge/Issues-welcome-blue?logo=github)](../../issues) [![Releases](https://img.shields.io/badge/Releases-latest-green?logo=github)](../../releases)

> **リスク警告**：本ツールはアクセシビリティサービスを通じて『エピックセブン』を自動操作します。
> **ゲームの利用規約に違反する可能性があり、アカウントリスクがあります**。使用は自己責任で、
> 本プロジェクトは Smilegate と一切関係ありません。

E7SA は『エピックセブン』の**秘密の商店**向け補助ツールです：スクリーンショット → 認識 → 判断 → タップ。
対象商品を自動購入し、買うものが無ければ商店を更新します。

- 言語：[简体中文](README.zh-CN.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

> **本ページは日本語版です。プロジェクトの主文書は中国語版 [README.zh-CN.md](README.zh-CN.md) で、
> 最新かつ最も完全な情報はそちらにあります。**（設定項目の全一覧は [docs/V1-配置能力矩阵.md](docs/V1-配置能力矩阵.md)）

## 概要

秘密の商店は 1 回の更新で 6 枠しか表示されず、対象商品の出現率は低い（1 枠あたり誓約の書籤 約 0.66%、
神秘のメダル 約 0.17%）。手動更新は負担が大きいため、「見る → 判断する → タップする」を自動化します。
目的は次の 3 点だけです。

1. **買い逃しゼロ** — 買える対象を見つけたら必ず買う；
2. **誤購入ゼロ** — 根拠が足りなければ、誤ってタップするより何もしない；
3. **予算の制御** — ゴールドと天空石（課金通貨）に上限を設ける。

**開発段階**：v1.0.0 が最初の公開版で、**個人プロジェクト**です（商用製品ではありません）。
**テストの完全性**：単体テストと敵対的テストはシミュレーション層で通過。実機検証はインストール・起動・
UI・クラウド同期のみ。**長時間の連続稼働は未検証**です（「テスト状況」参照）。

## 実装済みの機能

- **2 つの認識エンジン**：YOLO 視覚認識／従来型 CV（「購入」ボタン文字列から行構造を推定＋アイコン領域の色署名＋テキスト検証）
- **2 つの独立したタップ経路**：AI タップ（YOLO を目 + 専用の意思決定ステートマシン）と従来型タップ（テキストアンカー）。相互にフォールバックしません
- **予算ゲート**：ゴールド上限、天空石上限、書籤／メダル所持上限。到達したら停止
- **アイドル時の電力制御**：実行中は画面を点灯、タスク完了時に自動で画面オフ（設定可）
- **フローティングタスクパネル**：状態・段階・統計・イベントログ・開始/一時停止/停止（ドラッグ可）
- **記録**：セッション履歴、累計購入と消費
- **装備評価**：ステータス加重で装備の価値を算出（速度 x2.0／クリ率 x1.5／クリダメ x1.1／割合 x1／固定攻撃・防御 x0.3／固定 HP x0.15）
- **診断ツール**：生フレーム取得、認識リグレッション台（バージョン表示を長押し）
- **4 つのテーマ**（Steam ダークカード／Steam OLED ブラック／Blue Archive ライト／DeepSeek）と中国語・英語 UI
- **任意のクラウド同期**：WebDAV（自前のサーバーと認証情報）。設定しなければ通信は発生しません

*Experimental（利用可能だが検証中）*：スリープモード（全フレーム認識、遅いが安定）、
カスタム背景画像と上部タイトル画像、テーマ切替のイージング選択。

**実際の金銭に関わる修正**（最も重要な分類）：

| 問題 | 影響 | 状態 |
|---|---|---|
| 記帳が「検証成功」でゲートされていた | 動作は起きたのに検証が遅い／失敗すると記帳されない → 天空石のゲートが永久に発動せず、**課金通貨を無限に消費** | 修正済み（ACTION→COMMIT）、シミュレーション層で検証済み |
| タップが効いていないのに「処理済み」と記録 | 画面全体の買い逃し（AI 経路） | 修正済み、シミュレーション層で検証済み |

**安定性と安全性**：

- native 層の use-after-free（稼働中に装備評価ページを開くとクラッシュ）—— 修正済み、**実機での再現検証は未実施**
- モデル読み込みの失敗を検出できない（認識結果 0 なのにモデルは正常と報告）—— 修正済み、**未検証**
- Shizuku ワンタップ許可経路の破損（R8 が provider を除去）—— 修正済み、実機で検証済み
- 全デバイス共通のアクセシビリティ安全スイッチを無言で書き換え —— 修正済み（設定項目による明示的な許可に変更）、実機で検証済み

**その他**：メインスレッドのディスク I/O、評価エンジンのインデックス範囲外（トルコ語の 'İ' が文字を無言で飲み込む）、

`didScroll` が毎フレーム 17MB を確保、`handledRows` のスレッド間非同期。

## アーキテクチャ

```
スクリーンショット（アクセシビリティサービス）
  → 前処理（拡大縮小・切り出し、解像度非依存のサンプリング窓）
  → シーン判定（商店リスト／購入ダイアログ／更新ダイアログ／ネットワーク異常／その他）
  → 候補検出（YOLO アイコン枠 ∪ OCR 商品名行）
  → 特徴抽出（「購入」ボタンの行間から行構造、アイコン色署名）
  → OCR（PP-OCRv5）
  → マルチシグナル統合（テキスト＋アイコン傍証＋価格の一意一致）
  → フィルタ（売り切れ、処理済み行、商品種別スイッチ）
  → 意思決定（BotEngine 従来型／AiBotEngine AI）
  → 最終クリックゲート（ClickGate：座標の正当性、停止していないこと）→ ジェスチャ
```

- **層の分離**：認識層は「何が見えるか」、判断層は「何をするか」、デバイス層は「画面を取る・押す」だけ。
- **AI 経路はフォールバックしません**。不確実なときは報告して動きません。
- **ACTION → COMMIT**：状態を変える動作（購入・更新・予算減算）は**動作した瞬間**に記帳し、検証は以降の判断にのみ影響します。
- ネイティブ C++ が ncnn 推論を担当。モデルは `assets/e7sa_yolo.ncnn.meta` で自己記述されます。

## インストールと使い方

**要件**：Android 11（API 30）以上、arm64-v8a または armeabi-v7a。
実機検証は OnePlus PLR110 / Android 16 / ColorOS のみ。他の機種・ベンダー ROM は未検証です。

1. 本リポジトリの Releases から APK をインストールします。
2. アプリを開き、**アクセシビリティサービス**を有効にします（スクリーンショットとジェスチャに必須）。
3. 任意：adb で `WRITE_SECURE_SETTINGS` を付与するとワンタップ有効化が使えます：
   `adb shell pm grant com.e7.shop android.permission.WRITE_SECURE_SETTINGS`
4. リスク確認ダイアログに同意し、『エピックセブン』の秘密の商店を開いて「開始」を押します。
5. 先に**ゴールド上限**と**天空石の予算**を設定してください（0 = 無制限）。

**停止**：フローティングパネルまたはアプリ内の「停止」。再度「開始」すると前回を終了し、統計を初期化して現在の画面から再開します。

**復旧**：長時間動かない場合は、アクセシビリティサービスが有効か確認してください（アプリ更新後に OS が無効化することがあります）。アプリは一般的なケースを自己修復します。

**問題報告**：下記「バグ報告」を参照。

## セキュリティ検証とレッドチームテスト

### テストの目的

「動くことの証明」ではなく、**「壊れないことの証明」**です。

### テスト範囲と方法

- **範囲**：認識層への欺瞞（売り切れ行、偽の購入ボタン位置、行の誤タップ、価格の曖昧さ）＋タイミング欺瞞（確認タップが吸われる、ダイアログが消えない）
- **方法**：`RedTeamFsmTest` の敵対的ケース —— Attacker が攻撃対象の画面を構成し、被験体は意思決定ステートマシンそのもの。
  「設計どおりに動く」通常テストとは分離し、エンジンを騙せるシナリオを専門に構築します。

### テスト結果

| 攻撃シナリオ | 結果 |
|---|---|
| 売り切れ行 | **防線が阻止** —— 一度もタップしない |
| 偽の購入ボタン（「購入」テキストをアイコンの左側に配置） | **防線が阻止** —— タップしない（購入キーが候補の右側にあることを要求） |
| 行の誤タップ（行内は書籤、ダイアログはメダル） | **防線が阻止** —— 即座にその行を放棄してキャンセル、確認しない |
| 価格の曖昧さ／ダイアログ内容の不一致 | **防線が阻止** —— 購入を確認しない；3 回連続でその行を一時的に放棄 |
| ダイアログが永久に閉じない（タップがシステムに吸われる） | **防線が阻止** —— タイムアウトで保守的に計数するが、**偽の成功記録は絶対に書かない**（UNCONFIRMED のみ） |

### レッドチームが発見した問題（修正済み）

**RT-001｜決定的な失敗の無限リトライ**：同一行の `dialog verify FAIL`、購入キーが見つからない、
確認キーが見つからないという 3 種類の**決定的**な失敗は、以前は「タップが効かなかった」場合と出口を共有しており、
後者は「漏買より多く試す」方針で上限がありませんでした → 実測で同じボタンが **63 回 / 182 回**タップされています。
修正済み：独立した予算を追加し、3 回に達したらその行を**一時的に**放棄します（更新／スライドでクリアされ、恒久的なスキップではありません）。

**境界（重要）**：「タップが効かなかった（ダイアログが全く出ない、ボタンがまだ購入可能）」は**上限の対象外**です。
この経路は引き続き「その行を決して諦めない」—— 回復可能な失敗であり、諦めることは買い逃しに等しいためです。

### この検証が**そうではない**もの

- 完全なセキュリティ監査ではありません：範囲は上記の攻撃面のみで、ペネトレーションテスト、コード監査、形式検証は行っていません；
- 「問題が見つからなかった」は「絶対に安全」ではありません：レッドチームのケースが網羅するのは**既知の**失敗モードです；
- レッドチームのケースが検証するのは**意思決定ステートマシン**（シミュレーション層）であり、**実機の挙動を個別に再現したものではありません**。

   統計は先に WebDAV へアップロードし、再インストール後にダウンロードできます）。同一署名の版同士は上書きアップグレード可能です。
2. **アクセシビリティが外れる**：アプリの更新（`adb install -r` を含む）や `am force-stop` の後、
   システムのアクセシビリティ有効状態は**消去されます**（プラットフォームの挙動、RT-009）。
   更新後にアクセシビリティサービスが有効でないと表示されたら、もう一度有効にするだけです。
3. **署名キーの紛失 = 既存ユーザーへ更新を配布できなくなる** —— 独自キーを使う場合の固有のコストであり、ここに記録します。

## バグ報告とセキュリティ

- **通常のバグ**：[Bug Report テンプレート](.github/ISSUE_TEMPLATE/bug_report.yml) を使用し、バージョン、端末と Android のバージョン、再現手順、期待値と実際の挙動を記載してください。
- **公開 Issue に書かないでください**：アカウント、パスワード、端末のシリアル番号、個人パス、個人情報を含むログやスクリーンショット。
- **セキュリティ問題**（権限回避、データ漏洩、任意ファイルアクセス、第三者による悪用など）：
  公開 Issue ではなく [SECURITY.md](.github/SECURITY.md) に従い非公開で報告してください。
